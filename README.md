# 湘江中路

一个面向 GitHub Pages 的中文个人博客。基于 Astro 静态生成，包含首页、文章归档、关于页、Markdown 内容集合与文章详情页。

## 主题与交互

当前主题参考 [Rain 的博客](https://rainzt.cn/posts/auto-listing-update-2026-10-19/) 的页面布局与交互方式，在本项目中独立实现：全屏星河欢迎页、玻璃介绍卡、紧凑胶囊顶栏、作者侧栏、双列文章卡片，以及文章页的导读、正文和编号目录。保留本站文章、个人资料、分类与 BIM 演示。

默认顶栏随页面滚动，阅读时不会持续遮住正文。外观面板分为“外观、壁纸、偏好”三个页签，可调整卡片或专注布局、系统或文楷字体、深浅主题、色相、边框与光晕、四种壁纸模式、动态效果、正文字号及导航行为。设置保存在当前浏览器中。自定义壁纸在浏览器内压缩保存，不上传服务器。

本站提供关键词搜索、首页分类筛选与分页、分类及标签深链接、归档、RSS、文章目录高亮、阅读进度、图片放大和链接复制。日历和时间刻度按北京时间显示，文章数量来自实际内容。环境雨声由浏览器本地合成，点击后播放。文章交流入口使用邮件；尚未接入评论服务和访客统计后台。

星河场景是本项目自行绘制的 SVG，预先转换为 WebP 用于页面展示；没有使用参考站的人物插画、个人资料或品牌素材。轻量樱花粒子、卡片层次和页面过渡支持关闭动态，也尊重系统减少动态偏好。

霞鹜文楷屏幕阅读版字体来自 `lxgw-wenkai-screen-webfont` 1.7.0，采用本地 WOFF2 Unicode 分片按需加载。字体及来源说明位于 `src/assets/fonts/wenkai/`，保留了 OFL 许可文件。字体详情见该目录的 `README.md`。

## 动效与图片阅读

首页星河背景分为远景、月亮和近处樱花三层，桌面鼠标移动与轻微滚动产生不同幅度的位移。首页介绍卡和文章卡片具有小角度倾斜与柔和反光；文章列表在首次进入视野时短暂淡入。正文段落保持直接显示。触摸设备关闭鼠标视差与倾斜，减少动态偏好会关闭装饰运动，列表仍可完整访问。

深浅主题从操作按钮附近以圆形展开。在浏览器不支持视图过渡或用户减少动态时，直接切换主题。图片查看器支持滚轮、缩放按钮、双指缩放、放大后拖动、双击恢复，以及手机原始比例下的左右滑动切图。键盘方向键切图，`+` / `-` 缩放，`0` 恢复，`Esc` 关闭并回到原阅读位置。

背景分层源文件及 WebP 位于 `src/assets/images/scenery/`，均由本站原创星河 SVG 拆分。未增加动效框架。图片几何行为可通过 `npm run test:interactions` 检查，该检查也包含在日常 `verify` 中。

## 月湾樱花书屋

首页浏览顺序为欢迎页、三维书屋、文章列表。向下滚动接近书屋时自动加载引擎与模型，并以轻微的视角推进衔接入场。首页的工作室入口和滚动提示都指向同页书屋。`/studio/` 仍可独立访问，使用相同的自动载入与内容窗体验。

电脑、桥梁、书架、抽屉、樱花树和信封分别在同页内容窗中打开 AI 投标项目、BIM 实验室、技术笔记、文章归档、个人介绍与联系区域。桌面内容窗从右侧打开，可拖动标题栏移动、拖动右下角调整大小，并支持放大、缩小、最大化和最小化；手机使用可调整高度的底部抽屉。窗内文章链接继续在窗口中阅读，返回按钮保留本次阅读路径与滚动位置，关闭后回到书屋物件入口。

内容窗复用现有页面，保留图片查看器和 BIM 演示；嵌入阅读时隐藏重复的导航、侧栏和页脚，并跟随主页面的主题设置。场景标记和下方栏目仍保留真实链接，没有脚本时可以正常访问。桌面滚轮继续滚动页面，拖动可以旋转视角；触摸设备保留纵向页面滚动与双指缩放，手机通过下方栏目避免拥挤的模型标签。

场景沿用已确认的开放拱廊、深蓝星月背景、樱花树与月湾露台造型，支持日间和月夜灯光。减少动态设置会停止飘落与入场运动；视野外和后台暂停渲染。模型为本站原创的独立 GLB，位于 `public/models/moon-bay-studio.glb`，其源码为 `src/lib/studio/moon-bay-model.js`，运行 `npm run build:studio-model` 可重新导出。原参考图保留在 `design/meshy-reference/`，页面静态预览使用优化后的 WebP。

`npm run test:studio` 检查模型结构、六个物件分组和下载体积；`npm run test:interactions` 额外检查内容窗移动、缩放与手机边界；`scripts/check-studio-output.mjs` 检查首页顺序、自动载入、内容窗及控制、六个备用链接、联系锚点与发布路径。这些检查已纳入验证和发布流程。

## 本地开发

网站的页面、交互和样式保存在 `src/`，模型与视频等静态资源保存在 `public/`。发布当前本地版本时，需要将这些文件及相关构建脚本、测试和发布配置一起提交；只提交文章不会同步首页改版。

`design/` 保留设计参考、效果截图和早期模型，纳入版本管理用于查阅和回退，不属于博客文章内容。`.idea/` 是本机编辑器设置，`node_modules/`、`.astro/`、`dist/` 是依赖或生成产物，由忽略规则排除，线上构建会重新生成需要的发布文件。

要求 Node.js 24 或更高版本。

```bash
npm install
npm run dev
```

文章和代码的日常验证：

```bash
npm run verify
```

该命令执行类型检查、静态构建和图片验证，构建产物位于 `.astro/verify-dist/`，不会覆盖正在由预览服务使用的 `dist/`。修改文章后进行检查时，优先使用此命令。

需要更新正式构建或本地静态预览时：

```bash
npm run build
npm run test:images
npm run preview
```

`build` 与 `preview` 必须使用相同的 `BASE_PATH`。例如，预览服务以 `/blogNew` 为入口时，构建也必须设置 `BASE_PATH=/blogNew`。若预览期间用根路径 `/` 重建 `dist/`，HTML 中的 CSS 和图片地址会与服务入口不一致，导致资源返回 404、页面丢失样式。变更部署路径时，应停止原预览服务，再以相同配置构建并重新启动预览。

## 内容维护

AI 写作和改稿前，请先阅读 [个人博客 AI 写作规范](BLOG_WRITING_GUIDE.md)。其中包含读者定位、文章组织、难点解释、修改示例、自检清单和可复制的写作指令。根目录的 `AGENTS.md` 提供写作入口。

项目介绍与业务功能笔记面向不熟悉项目实现的读者。写作时应从实际工作场景出发，讲清功能解决什么问题、使用者如何操作、结果如何理解，以及难点为何会影响使用体验。语言保持严谨，必要概念用具体例子解释。

文章正文不展示项目代码、配置键、接口地址、数据库字段、类名或源码路径，也不按前后端调用顺序组织内容。实现细节用于核实事实，写入文章时应提炼为读者能够理解的业务过程、设计考虑和能力边界。

文章位于 `src/content/blog/`。复制任意 Markdown 文件并修改 frontmatter 即可新增文章。设置 `draft: true` 可让文章保留在仓库中但不参与构建。

旧 Hexo 博客内容可通过 `node scripts/migrate-old-blog.mjs` 重新转换。脚本只读取 `F:/blog/restored-blog/source/_posts`，输出到当前项目的 `src/content/blog/`。
旧图床资产可通过 `node scripts/download-old-assets.mjs` 重新下载；需要本地代理时，先设置 `OLD_BLOG_PROXY`，例如 `http://127.0.0.1:7890`。

站点名称、作者、邮箱和 GitHub 地址集中在 `src/config.ts`。图片放在 `src/assets/images/`，文章里的 `cover` 使用相对于 Markdown 文件的路径，例如 `../../assets/images/about-sky.jpg`。正文也使用 Markdown 图片语法：`![图片说明](../../assets/images/posts/项目名/图片.png)`。

图片由 Astro 在构建时自动生成 WebP 和多尺寸版本，浏览器通过 `srcset` / `sizes` 选择合适的文件。首页背景优先加载，列表封面、头像和正文图片按需加载；无需额外图片服务器，GitHub Pages 和 EdgeOne 都可直接发布构建结果。不要把需要优化的图片放回 `public/` 或使用原始 `<img>` 标签，否则会绕过这条处理流程。

## 文章底部的演示视频

所有文章都可以配置一个或多个演示视频，位置在正文及文章自带演示之后、阅读操作与相关文章之前，每个视频会分别加入文章目录。没有配置视频的文章不显示播放器或空白占位。

将实际 MP4 或 WebM 文件放到 `public/videos/` 后，在对应文章的 frontmatter 中加入：

```yaml
demoVideo:
  src: "/videos/demo.mp4"
  title: "演示视频"
  description: "在这里填写视频说明。"
```

`title`、`description` 可省略。封面默认使用文章封面，也可增加 `poster`，填写相对于当前 Markdown 的图片路径，与文章 `cover` 的写法相同。

同一篇文章放置多个视频时，使用 `demoVideos` 列表，按从上到下的展示顺序填写：

```yaml
demoVideos:
  - src: "/videos/tutorial.mp4"
    title: "使用教程"
  - src: "/videos/demo.mp4"
    title: "演示视频"
```

已有的 `demoVideo` 单视频配置仍可使用；若与 `demoVideos` 同时填写，单视频会排在列表后面。每个视频都有独立的目录入口和标题定位。

`src` 也可以是 HTTPS MP4/WebM 直链，或完整的 B 站、YouTube 视频地址。B 站支持 BV/av 地址和分 P；YouTube 支持观看页、分享短链接和 Shorts。B 站的 b23.tv 短链需先展开为完整视频地址。

本地视频默认不自动播放，使用 `preload="none"`，保留手机内联播放、进度、音量和全屏操作。平台视频先显示封面，只有读者点击后才加载第三方播放器；没有脚本时仍可通过下方链接到原站观看。

直接播放的视频可选配 WebVTT 字幕：

```yaml
demoVideo:
  src: "/videos/demo.mp4"
  captions:
    src: "/videos/demo.zh-CN.vtt"
    language: "zh-CN"
    label: "中文字幕"
```

平台视频的字幕在对应平台维护。使用外部字幕时，视频和字幕所在服务器需允许匿名跨域请求。视频本身建议使用通用的 MP4（H.264 视频、AAC 音频）；较长的视频可使用平台链接或对象存储直链，减少仓库与站点的资源负担。

`npm run verify` 和发布流程会检查配置、播放器属性、本地视频/字幕文件及部署前缀。也可单独运行 `npm run test:videos` 检查已有 `dist/` 产物。示例文件名只是配置说明，仓库没有为正式文章填入测试视频。

## GitHub Pages 发布

1. 在 GitHub 创建空仓库并推送本项目，默认分支使用 `main`。
2. 打开仓库 `Settings > Pages`，将 Source 设为 `GitHub Actions`。
3. 推送到 `main`，或在 Actions 中手动运行 `Deploy to GitHub Pages`。

工作流会自动区分两类地址：

- 用户站仓库 `USERNAME.github.io`：部署到域名根路径。
- 普通项目仓库：部署到 `https://USERNAME.github.io/REPOSITORY/`，资源和链接会自动加仓库前缀。

自定义域名时，在仓库 `Settings > Secrets and variables > Actions > Variables` 设置：

- `SITE_URL`：例如 `https://notes.example.com`
- `BASE_PATH`：通常为 `/`

完整运维判断、回滚与域名操作见 [OPERATIONS.md](./OPERATIONS.md)。
